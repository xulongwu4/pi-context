# pi-context

Context insight for [pi](https://github.com/earendil-works/pi), modeled on [dsh-context](https://github.com/bowenliang123/dsh-context).

## Install

```sh
pi install /path/to/pi-context   # permanent
pi -e /path/to/pi-context/src/index.ts   # one run
```

## Features

- `/context` opens an overlay with thirteen tabs.

  | Tab | Content |
  | --- | --- |
  | Stats | Context window use, human inputs, requests, tool calls, cost, token totals, the tokens sent over the session by category, prompt cache use, requests and cost per model, timing. With subagents: the tokens and cost of the session together with them. With stream timing: the average time to the first token, the output tokens per second, and the share of the stream time spent on thinking, tool calls and answers. The prices of the models per million tokens, when pi knows them |
  | Current | Composition of the current context by category, a strip of its items in reading order, and the items, largest first or in reading order. Under the composition: where pi's compaction starts, the room left before it, and the output limit of the model |
  | Hints | What could be dropped from the context, the tokens that would free, and what was dropped |
  | Turns | One row per human input: its requests, tool calls, tokens, cost and duration, and the time it waited for the user to answer questions |
| Trend | Tokens sent by each request, the share read from the prompt cache, and cache misses; or the tokens sent by the last request of each human input; or the change from one request or input to the next. One line shows the whole session. Under the selected bar, three lines tell what the request did: `User`, the human input it works on; `In`, what entered the context since the request before; `Out`, the tools the model called and the start of its answer. Each bar shows the recorded duration and marks: `✂` compaction, `▾` drop, `▴` restore, `✓` task done, `□` task created, `?` question to the user, `◷` the slowest bar, `↑` the largest growth of the context, `→` delegation, `←` message of a subagent, `◆` skill loaded, `⇄` model change. The selected bar also shows its human input and its step in that input, the time to the first token, the input, cache read, cache write and output that the provider reported, and the estimate by category |
  | Browser | What one request was assembled from, in reading order, and what changed since the request before it: items added, changed and removed, and the items and tokens each category gained or lost. The comparison can instead take the last request before the human input. The list can hold only the thinking, the tool calls or the answers; the number of each is shown. A tool result opens with its call: the tool, the status, the number of lines and the arguments. With recorded declarations, the list can hold the tools that the request declared: the size of each schema, its source and its calls in that request |
  | Events | Injections by extensions and skills, compactions, dropped and restored tool results, model switches, thinking level changes, branch summaries, questions to the user, delegations, and tasks created and done: the number of events of each kind, the request each event followed, and the tokens it added to the context or took from it. A compaction shows the number of messages it replaced and their estimated tokens. A table sums the injections by the extension message type or the skill that made them |
  | Files | Reads, writes, edits, searches and image reads per file, and the lines the writes and edits added and removed. The list can hold only the files with one kind of operation, most operations first, last used first, by path or most changed lines first. A file opens into its operations, newest first: the time, the request that made the call, the tool, the lines it changed or the hits of a search, and the lines of a partial read |
  | Commands | Shell commands, newest first: the result of each, the request that ran it and the time it took. Above the list: the number of commands, the failed ones, the time they took together, the programs they ran, and the number of commands that succeeded, failed or have no known result. The list can hold only one of these. `Attention` names the slowest command, the program that failed most and the command repeated most. Every program of a pipeline or a chain counts. A time of 10 seconds or more is highlighted, and a command of several lines, with a heredoc or with an inline script is tagged. The list can also hold only the slow commands or the commands of one `Attention` entry, or show the slowest first. A command opens into its whole text, its exit code, whether it timed out, was aborted or had its output truncated, the number of lines it printed, and its output |
  | Tools | Calls, errors and estimated tokens per tool, the size of its schema and who provides it (pi, an MCP server, a package or an extension file), the tool schemas summed by source, and the skills that were loaded. Declared tools that were never called are listed too. A tool opens into its description and parameters, when pi knows the tool now |
  | Fleet | Three views, under a line with the number of subagents, of those running, of tasks and delegations, and of messages. Agents: the main agent and its subagents, each under the agent that started it, with status, time, model, requests, tokens, cost, context size, share of the window and composition; the selected subagent also shows its prompt, its reply, its tasks and its last events. Timeline: delegations, messages to subagents, result reads, completion notifications, completions and task changes in order of time. Tasks: the tasks of pi-tasks by owner and the delegations by agent type, with the status and the unfinished tasks that block each; a pending task that nothing blocks shows `ready`, and a task opens with the tasks it depends on, nearest first |
  | Insights | The last 7, 30 or 90 days or all time, over all projects or the current one, or one day of that period: totals, human inputs, tool calls, active time and the cache-hit rate, a calendar of the tokens, requests, sessions or cost by day, the sessions of each day, a 7-day chart, activity by weekday and hour, the tokens sent by category, requests and cost per model, cost per project, top tools, programs and skills with the number of sessions that used each, the time each was last used and where a skill comes from (project, user or package), and the sessions with the context size and the composition of each |
  | Settings | The context warning, auto-compact, the cost budget, the cache expiry warning, the footer, the system prompt prefix and suffix, and the view defaults |

  Keys: `←`/`→` tab, `↑`/`↓` scroll or select, `[`/`]` previous or next request, `r` refresh, `q` close.

  | Tab | Keys |
  | --- | --- |
  | Turns | `enter` opens the first request of the selected input in Browser |
  | Files | `enter` lists the operations on the selected file; `enter` on an operation selects its tool result in Browser, or in Current when no request followed; `esc` goes back to the files. `k` lists the files with one kind of operation, then the next kind, then all again; `s` changes the order; `a` shows the files as they were after the selected request, and `a` again shows all |
  | Commands | `enter` shows the whole command, how it ended and its output; `esc` goes back. `b` selects the tool result of the selected command in Browser, or in Current when no request followed. `k` lists the commands with one status, then the next, then all again; `f` selects the next failed command; `s` selects the slowest one. `l` lists only the slow commands, `o` lists the slowest first, and `a` lists the commands of the next `Attention` entry, then all again |
| Trend | `enter` opens the selected request in Browser, at the first item added since the request before; `g` switches between one bar for each request and one for each human input; `m` switches between totals and changes |
  | Current, Browser | `enter` shows the whole content of the selected item, a tool result with its call; `esc` goes back |
  | Browser | `k` lists only the thinking, then the tool calls, then the answers, then the tools that the request declared, then all again; `b` switches the comparison between the request before and the last request before the human input |
  | Current | `o` switches the list between largest first and reading order |
  | Current, Hints | `d` drops the selected tool result from the context, `u` restores it |
  | Tools | `↑`/`↓` select a tool, `enter` shows its description and parameters, `esc` goes back; `s` changes the order: most called first, largest schema first, or by name |
  | Current, Browser, Files, Commands, Tools, Insights, Fleet timeline | `/` starts a filter: type text, `enter` keeps it, `esc` clears it. Only lines that contain the text stay |
  | Events | `k` lists one kind of event, then the next kind, then all again |
  | Insights | `p` changes the period, `[`/`]` narrow the tab to one day, `a` switches between all projects and the current one, `s` changes the order of the sessions (newest, cost, tokens, context size), `g` groups them by project, `enter` opens the selected session. `t`, `c` and `k` list only the sessions that used the next top tool, program or skill; `x` lists all sessions again. `m` changes what the calendar shows by day: tokens, requests, sessions or cost |
  | Fleet | `v` changes the view. Agents: `enter` opens the session of the selected subagent. Timeline: `enter` shows the content of the selected event, `o` switches between earliest and latest first. Tasks: `enter` shows the description and the reply, `k` lists the tasks in one state (in progress, pending, done), then the next, then all again. `n` keeps in Timeline and Tasks only the agent of the selected entry; `n` again or `esc` shows every agent |
  | Settings | `enter` edits the selected setting, or sets the next value of a view default; `x` clears it |

  While the agent or a subagent runs, the overlay refreshes every second and shows `● live`.

  A session opened from Insights or Fleet is read-only and shows the branch that ends at the last entry of its file. `esc` returns to the current session.

  In Insights and Fleet, `↑`/`↓` scroll the tab until the selected entry is in view, and then move the selection.

  In Insights, the first `[` selects today. Then `[` and `]` select the day before or after, and `]` on today shows the whole period again. The calendar marks the selected day with `[]`.

  In Current and Browser, the strip shows the prompt from its first token to its last, colored by category, and `▲` marks the selected item. Each item shows `#`, its position in the prompt, and `@`, the first request that carried it.

  A request number can be followed by its place: `#12 3.2` is request 12, step 2 of human input 3.

- Dropping tool results: `d` in Current or Hints replaces a tool result with a one-line stub in every later request. The session file keeps the original, and `u` restores it. The request after a change reads less from the prompt cache, because the context differs from the dropped result on.
- Footer indicator: `ctx 42% 84.2k/200.0k`. It updates after each turn. `/context footer <items>` chooses what it shows, from `context`, `cost` (session cost), `cache` (share of the sent tokens read from the prompt cache) and `ttl` (estimated time until the prompt cache expires). Example: `/context footer context cost ttl`.
- Cost budget: `/context budget <dollars>` gives one warning when the cost of the session reaches the amount, and adds the cost to the footer. `/context budget 0` removes it.
- Cache expiry warning: `/context expiry <seconds>` gives one warning that many seconds before the prompt cache expires, when the agent is idle at that time. A request sent after the expiry sends the whole context without the cache. `/context expiry 0` turns the warning off, which is the default.
- Auto-compact: `/context compact <percent>` starts pi's compaction when the agent stops and context use is at that percentage or above. `/context compact 0` turns it off. It is off by default.
- Context warning: one notification each time context use rises to 80%. It names the largest category. `/context warn <percent>` changes the percentage, `/context warn 0` disables the warning, and `/context warn` shows the setting.
- `/context prefix [text]` and `/context suffix [text]` set text joined to the start or end of the system prompt. Without text, an editor opens. An empty value disables the setting. The change applies from the next turn.
- View defaults: `/context view <name> <value>` stores how a view opens, in the overlay and in the web page. The names are `period` (Insights: `30`, `7`, `90` or `all` days), `trend` (one bar per `request` or per human `input`), `mode` (`total` or `change`), `tools` (order `calls`, `schema` or `name`), `files` (order `ops`, `recent`, `name` or `lines`), `fit` (the web page opens the Context Trend whole with `off`, or with its last `100`, `200` or `300` bars) and `diff` (Browser compares with the previous `request` or with the last request before the human `input`). Without a value, the next value is set. `/context view` lists the defaults.
- `/context export [file]` writes all tabs to a Markdown file. The default is `pi-context-<session id>.md` in the working directory. A file name that ends in `.json` gets the same data as JSON.
- The `context_insight` tool gives the model a text report of its own context. Its optional `section` parameter returns one part in more detail: `composition`, `requests`, `tools`, `files`, `commands` or `hints`.

## Web page

`/context web` serves the dashboard as a web page and opens it in the browser. It also shows the address, for example `http://127.0.0.1:38811/?t=9ac7…`.

- The Context page shows the current session in cards: Context Stats, Token Stats, Timing Stats, Current Context, Context Browser, Context Trend, Hints, Turns, Context Events, File Activity, Command Executions, and Tools, Skills and Models. A session with subagents or tasks also shows Agents, Collaboration Timeline and Tasks Board.
- In Context Stats, a tile or a link with a card behind it scrolls to that card. With subagents, the card shows the totals of the session together with them. With stream timing, it shows the time to the first token and the output tokens per second, and Timing Stats shows how the reply streams split into reasoning, tool calls and answers. `Prices per million tokens` lists the prices of the models.
- A link in Context Stats can also filter the card it opens: `compactions` lists the compactions in Context Events, `failed` the failed commands, `edited` the edited files, a tool its row in Tools, and a program its commands.
- In Current Context, the hatched end of the bar is the part of the window that pi's compaction keeps free. The line under the bar tells where compaction starts, the room left before it, and the output limit of the model. `Treemap` shows one area for each item, grouped by category.
- In Context Trend, each bar is one request, split by category. Click a bar to open the request in the Context Browser. The marks are those of the overlay, and `!` marks a cache miss; the legend lists the marks that occur; a bar shows one mark and its tooltip names all. The strip under a bar is the recorded duration of the request. For the selected request, a line shows the input, cache read, cache write and output that the provider reported, and the categories show their estimates.
- Under the chart, three lines tell what the selected request did. Click `User` to open the first request of the human input, `In` to show the first item that entered the context since the request before, and `Out` to show the answer in the context of the next request. With `By input`, `In` and `Out` cover all the requests of the input.
- `By input` shows one bar for each human input: its last request. `Changes` shows each bar as the change since the bar before, by category: what grew is above the line, what shrank is below it. `Fit` fits the whole session into the width of the card. With the view default `fit`, a longer trend opens with its last 100, 200 or 300 bars, and `Show all` shows the rest.
- In the Context Browser, click a category to list its items and an item to show its whole content. The select and the `‹` `›` buttons change the request. A request shows what was added (`+`) or changed (`~`) since the request before it, and the items and tokens each category gained or lost. `Diff: human input` compares with the last request before the human input instead. `Only added and changed items` lists nothing else. The chips `Thinking`, `Tool calls` and `Answers` keep only that part of the replies and show how many items it has. A tool result opens with its call: the tool, `OK` or `error`, the number of lines and the arguments.
- A request number shows the place of the request after it: `#12 · 3.2` is request 12, step 2 of human input 3. `Go to` in the Context Browser finds a request by its number, by its place or by text of a human input.
- With recorded declarations, the open category of the tool schemas lists the tools that the selected request declared, with a search box and the orders `Size`, `Name` and `Calls`; click a tool to show its description.
- The strip in the Context Browser has one band per item, in reading order. Click a band to show its item. `One list, in reading order` lists the items of all categories together. Each item shows `#`, its position in the prompt, and `@`, the first request that carried it.
- The content of an item opens as `Text`, as `Markdown` (headings, lists and code only), or as indented `JSON` when it is JSON. `Copy` copies what is shown. The find box highlights the matches; `Enter` goes to the next one and `Shift`+`Enter` to the one before.
- `Drop` and `Restore` on a tool result, in the Context Browser or in Hints, do what `d` and `u` do in the overlay.
- In Context Events, the buttons list one kind of event or all. A compaction shows the number of messages it replaced and their estimated tokens. The number in the After column opens that request in the Context Browser. `Injected by` sums the listed injections by the extension message type or the skill that made them.
- In File Activity, the chips `Read`, `Written`, `Edited`, `Searched` and `Images` keep the files with such operations, and `Operations`, `Last used`, `Path` and `Lines` change the order. `Filter paths` keeps the files whose path contains the text. `As of the request` shows the files as they were after the request that the Context Browser shows. Click a file to list the operations on it; a search shows its hits, and a partial read its lines. The request number of an operation shows the tool result of that operation in the Context Browser.
- In Command Executions, the chips `OK`, `Failed` and `Unknown` keep the commands with that result. `Next failed` highlights the newest failed command, then the one before it; `Slowest run` highlights the command that took longest. `Worth a look` names the slowest command, the program that failed most and the command repeated most; click an entry or a program to list its commands. `Slow` keeps the commands of 10 seconds or more, and `Order` lists the latest or the slowest first. Click a command to show its whole text, how it ended and its output. `Filter commands` keeps the commands that contain the text. The Programs column lists every program of a command. The request number of a command shows the tool result of that command in the Context Browser.
- In Tools, Skills and Models, each tool shows the size of its schema and who provides it. `Calls`, `Schema` and `Name` change the order. Click a tool to show its description and parameters. A second table sums the tool schemas by source.
- Agents shows one card per subagent under the agent that started it: status, model, context size against the window, composition, requests (`Steps`), run time, tool calls, tokens and cost; click a card to show the prompt, the reply, the tasks and the last events of the agent, and to keep only that agent in the timeline and the board; `Filtered to` shows every agent again. Collaboration Timeline lists the events latest first; `Earliest first` turns the order, the chips keep one kind of event, the search box filters, and a click shows the content of an event. Tasks Board groups the tasks by owner and the delegations by agent type; the chips keep one state, a click shows the description and the reply, `Search tasks` filters, `ready` marks a pending task that nothing blocks, `blocked by #id` shows the blocking task, and an open task lists the tasks it waits for.
- The Settings card changes the context warning, auto-compact, the cost budget, the cache expiry warning, the footer, and the system prompt prefix and suffix. An empty number restores the default. Under `View defaults`, a select for each default saves the choice at once and applies it to the open page.
- The Insights page shows the last 7, 30 or 90 days or all time, over all projects or the current one. `Today` or a click on a day in the calendar narrows the page to that day; a second click shows the whole period again. `Shift` and a click on a second day select the days from one to the other. The tiles include the cache-hit rate, human inputs, tool calls and active time. The calendar tells the sessions of each day. Each tool, program and skill shows the number of sessions that used it and when it was last used, and a skill shows where it comes from; click one to list only the sessions that used it, and click it again or `Clear` to list all. `Shaded by` changes what the calendar shows by day: requests, tokens, sessions or cost. Each session shows its inputs and requests, its context size with its share of the window of the model, and a composition bar; `current` marks the session that is open in pi. The sessions can be ordered by context size and grouped by project. Click a session to open its Context page. A saved session is read-only.
- The page loads the data again after each request and each turn of the current session, at most every 2 seconds.

The server listens on `127.0.0.1` only, on a free port. Every request for data must carry the token of the address, so keep the address to yourself: it gives read access to the content of the session and of the sessions that Insights lists, and it can drop tool results and change the settings. To use the page from another machine, forward the port, for example with `ssh -L`.

The server stops when the session ends, also on `/new`, `/resume` and `/reload`. `/context web stop` stops it earlier. Each pi session has its own server and address.

The page needs no build step: `web/` holds one HTML file, one style sheet and one script.

## Stored data

- Settings and view defaults are in `pi-context.json` in the pi agent directory.
- At the end of each turn, the extension appends one `pi-context:turn` entry to the session. It holds the duration of the request, the time to the first token, the stream time of the thinking, the tool calls and the answers, the tool time, the composition by category, the file of each anchor-based edit, and the tool declarations with the source of each tool when they changed. Pi does not send these entries to the model.
- Each time a tool result is dropped or restored, the extension appends one `pi-context:prune` entry with the ids of the dropped tool calls. The last entry on the branch applies, so the dropped results follow the branch and survive a resume.
- Insights caches one summary per session file in `pi-context-cache.json` in the pi agent directory. Only new or changed session files are read again; a new version of pi-context that changes the summary reads all of them once. Summaries of files unchanged for 120 days are dropped, so the period `All` reads those files again.

## Accuracy

- Totals (context size, tokens, cost) are the figures the provider reported.
- Figures marked `≈` are sizes at 4 characters per token, scaled so that they add up to the provider-reported size of the context. The scale factor is shown below each composition. Without a provider-reported size, for example before the first request, the figures are not scaled.
- The scaling is needed because 4 characters per token is too high. In sessions measured on three model families, a token was 2.8 to 3.7 characters. A proxy or provider can also add content that pi does not see. One factor applies to all categories, so the shares are those of the character counts.
- When a proxy shortens the context after pi has built it, the factor is below 1 and all items shrink alike. The extension cannot tell which items the proxy shortened.
- A cache miss is a request that read less than half of the previous request from the prompt cache, with the same model and no compaction between them. The extra cost is an estimate: the tokens billed again, at the rate the request paid for input and cache writes, less the cache read rate.
- Hints lists reads that a later read with the same arguments supersedes, skills loaded more than once, and the ten largest tool results of at least 1000 estimated tokens from before the last user message. For reads made inside a script, Hints only names the files read more than once, with the size of the file times the earlier reads as an upper bound; these are not in the total, and they cannot be dropped alone because they are part of the script's result. The list is advice. The extension removes nothing unless you drop it.
- Skill injections are the list of available skills in the system prompt, the skill files that `/skill:name` inputs load, and the results of reading a `SKILL.md` file. The System prompt figure leaves the list out. A `/skill:name` input counts as a load of the skill in Tools and Insights. Requests that an earlier version recorded count the list as System prompt.
- Tool schemas are the declarations in the provider request, because a request can leave out declarations of active tools, as codemode does in `only` mode. The extension reads them from each request and records them in the session. Before it has seen a request in a session, it takes the active tools from the session and leaves out the ones pi reports as hidden.
- A dropped tool result stays dropped only while the extension is loaded: the extension replaces it in each request. Compaction summarizes the original, not the stub. Browser rebuilds an earlier request without the drops of that time.
- "Sent over the session, by category" in Stats covers the requests that have a turn record. It scales the recorded composition of each request to the size the provider reported for it.
- In Turns, the duration is the time from the input to the last message it caused, without the time that a question tool (`ask_user_question`, `AskUserQuestion`, `questionnaire`) waited for the user. The active time of that request and the tool time in Stats leave that time out too. The wait of any other tool is included.
- The Browser comparison matches items by content. The system prompt, the tool schemas and a tool result keep their identity, so they show as changed (`~`) and not as removed and added.
- The time until the prompt cache expires is an estimate: 5 minutes after the last request, or 1 hour when a request of the session wrote to the 1-hour cache. It is shown only for models that have used the cache in the session. The cache expiry warning uses the same estimate, and it does not appear while the agent runs or when pi has no UI.
- The change that Events shows for a compaction is the size of the request after it minus the size before the compaction, so it includes what was added in between. A compaction without a later request shows no change. The change of a drop or a restore is the estimated size of the tool results at 4 characters per token; the stub that replaces a dropped result is not counted.
- An injection event is a message that an extension put into the context, a `/skill` input, or a skill file that the model read. The session names an extension message by the type the extension gave it, for example `wiki-recall-context`, not by the extension. A skill file read by a script is no injection: its content goes to the script. The system prompt, with its context files and the skill catalog, is no event.
- Auto-compact acts when the agent stops, not between the requests of one run. Pi refuses to compact a session that is too small.
- In the web page, a grey bar in Context Trend is a request without a turn record: its split by category is not known. The Context Browser rebuilds such a request from the session when you open it.
- A change in Trend is the difference of the provider-reported sizes of two requests. Its split by category needs a turn record of both requests, each scaled to the size of its request. The bar of a human input shows the context after the last request of the input; the web page marks the bar when any request of the input followed a compaction or missed the cache.
- The duration in Trend is the time of the request from its turn record; a request without a record shows none. The bar of a human input shows the sum of its requests. A mark for an event is on the first bar after it.
- The time to the first token runs from the moment pi sends the request to the first stream event of the reply. Output tokens per second divide the output of the requests that have stream timing by their time after the first token. Sessions recorded by an older version have no stream timing.
- The `◷` mark is on the bar with the longest duration and `↑` on the bar whose context grew most since the bar before.
- A program is the first word of each part of a pipeline or a list of commands. Variable assignments, wrappers (`sudo`, `doas`, `env`, `timeout`, `nice`, `time`, `exec`, `nohup`, `command`, `stdbuf`, `caffeinate`, `noglob`, `nocorrect`), the bodies of heredocs and quoted text do not count. `cd` counts only when the command runs nothing else.
- The exit code of a command, a timeout and an abort come from the status line that pi's bash tool appends to the result. A command made by a script has none.
- The tokens that a compaction replaced are the messages it summarized, at 4 characters per token and not scaled.
- The tools that a request declared are the declarations that pi-context recorded at or before that request, with the sources recorded then. A request from before the first record lists none.
- The totals with subagents add the tokens and cost that each subagent reported. A subagent that reported none adds nothing.
- The reserve in Current is two settings: the tokens that pi's compaction keeps free (`reserveTokens`, when compaction is on) and the largest answer of the model (`maxTokens`). Pi starts its own compaction when the context grows into the first one. A saved session shows no reserve.
- With the diff baseline `input`, Browser compares a request with the last request before the human input it belongs to. A request of the first human input has no such request and shows no comparison.
- The `In` line of Trend comes from the session: human inputs, tool results, `!` commands, messages of extensions, and compaction and branch summaries, each at 4 characters per token and not scaled. It does not show what an extension changed in the context of one request, nor a changed system prompt or tool schema; Browser shows those.
- Requests, events, file activity, commands and tool counts come from the session branch, so they cover a resumed session.
- Timing and the recorded composition cover the turns that ran while the extension was loaded. For other requests, Browser rebuilds the composition from the session and says so. A rebuilt composition does not show changes that other extensions made to the context before the request was sent.
- The first request that carried an item is the first request made after the message of the item was created. The system prompt and the tool schemas have no such time and show none. An item that no request has carried yet shows none either. In the overlay, the strip does not show an item smaller than one cell.
- File activity counts tool calls named `read` or `write`, or matching `edit|replace|insert|patch`, and searches. Edit tools that address lines by anchor name the file only in their result, so their file is known only for turns that ran while the extension was loaded. The Files tab says how many such edits it cannot list.
- The lines an edit added and removed are counted in the diff that the edit tool returns. An edit made by a script returns its diff only to the script, so its lines are known only for turns that ran while the extension was loaded. Without a diff, the lines are estimated from the `oldText` and `newText` arguments. A write counts every line of its content as added, and nothing as removed: the session does not tell what the file held before. The totals of a file sum the operations whose lines are known. A failed operation counts as an operation and changes no line.
- The result of a file operation or a command made by a script is the result of the script: the session keeps no result for the nested call.
- A search is a call of `grep`, `find`, `glob`, `rg`, `ffgrep` or `fffind`. It counts once on each file that its result lists, for at most 100 files, and a search of file contents shows the number of matching lines in the file. A search that found nothing counts on the searched path. So does a search made by a script, without hits, because the session keeps no result for it.
- An image read is a `read` whose result holds an image. A `read` made by a script is an image read when the file name ends in `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp`.
- The time a command took is the time pi saved with its tool result, or with the nested call of a script. A session that has no such time shows none. A command that the user ran with `!` shows `user` in place of a request, and no time.
- The Tools tab marks a tool with `!` when the model called it directly although it is not declared to the model. This happens in codemode `only` mode: a hidden tool stays active, so a direct call by name still runs. Each call is judged by the declarations the extension recorded for the request that made it. Calls made before the first record are judged by the tools declared now.
- The source of a tool is `mcp:<server>` when its name is `mcp__<server>__<tool>`, `pi` for a built-in tool, the package for a tool of a package, and the name of the extension file otherwise. Pi tells the source only of the tools that are loaded now. For a saved session, the sources are those recorded with the tool declarations; a session recorded by an earlier version shows only MCP servers. The whole content of the tool schemas item in Current and Browser lists each schema with its size and source.
- The Schema column shows the declarations of the last request, not those of the request that made a call. A tool that was called and is no longer declared shows no schema.
- Calls nested in another tool's result, for example from a script, are counted. Their tokens belong to the tool that made them. The size of a skill loaded by a nested call is the current size of its file.
- Fleet needs [pi-subagents](https://github.com/tintinweb/pi-subagents). Finished subagents come from the records it saves in the session. Model, requests, tokens, cost and context size come from its live events, or from the subagent's saved session when there is one. The context size of a running subagent is the prompt of its last request. The window is the context window that pi knows for the model of the subagent; without it, no occupancy is shown.
- The composition of a subagent shows the shares of the messages in its saved session, by their size in characters. The system prompt and the tool schemas are not in it. A running subagent, and a subagent without a saved session, shows none.
- pi-subagents reports the start and the end only of the subagents that the main agent started. A subagent of a subagent shows `nested` as its status, with the usage of its requests, and it is not on the tasks board.
- The Fleet timeline lists what the session holds: delegations (calls of `Agent`), messages to a running subagent (`steer_subagent`), result reads (`get_subagent_result`), completion notifications, the saved completion records with the final reply, and task changes (`TaskCreate`, `TaskUpdate`). pi-subagents has no channel for messages between subagents, so the timeline has none. A delegation made by a script has no result in the session; it is matched to the subagent with the same type and description.
- The tasks board reads the task list of [pi-tasks](https://github.com/tintinweb/pi-tasks) from the file that pi-tasks uses for the session (`PI_TASKS`, or the `taskScope` of `tasks-config.json`). With the scope `memory` there is no file and the board lists only the delegations. A task shows only the blockers that are not completed. A delegation is in progress while its subagent runs, pending while it is queued, and done otherwise.
- The Insights project filter counts sessions that ran in the working directory or below it. The per-session figures in its session list cover the whole session, also the part before the period.
- With one day selected in Insights, the totals, the hours, the categories, the models, the projects and the top lists cover that day. The calendar and the 7-day chart still cover the period. The top tools, programs and skills count the whole of each session that has a request on the day or in the period.
- The Insights calendar shows the last 53 weeks at most. The totals of `All` also count what is older. A day is a day in the local time zone.
- The Insights tokens by category cover the requests that pi-context recorded, like the same figure in Stats.
- Insights counts each session's own requests. A subagent's work is included when its session was saved.
- In Insights, human inputs and tool runs count in the hour of the human input, and a tool run made by a script counts too. Active time is the time the agent worked in the turns that pi-context recorded. The cache-hit rate is the share of the sent tokens that the requests of the period or day read from the prompt cache.
- The time a tool, a program or a skill was last used is the time of its last use in the sessions that count, also when that use is outside the selected day.
- Selecting a tool, a program or a skill in Insights narrows only the session list. The figures, the charts and the top lists still cover all sessions.
- The context size of a session in Insights is the prompt of its last request. Its composition bar is the recorded composition of its last recorded request, so a session that pi-context did not record shows no bar.
- The share of the window that Insights shows for a session uses the window of the model of its last request, as pi knows that model now.
